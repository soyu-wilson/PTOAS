# `tvec` dialect (scaffolding)

`tvec` ("tiled vector") is the **machine-independent** dialect that connects the
virtual tile level (`pto`, `pto.tadd` on `!pto.tile_buf`) to the hardware ISA
level (`vpto`, `vpto.vlds` on `!vpto.vreg<64xf32>`). It hosts the explicit
`scf.for` loop nest while keeping the operations hardware-neutral, which is the
level at which **loop fusion** runs.

Full rationale, op listing, lowering pipeline, and the loop-fusion design are in
[`docs/designs/tile-to-hardware-dialect-layering.md`](../../docs/designs/tile-to-hardware-dialect-layering.md).

## Status

This is **RFC scaffolding**. The TableGen + headers here are deliberately **not**
wired into the top-level build (`include/CMakeLists.txt` does not
`add_subdirectory(Tvec)`), so the existing toolchain builds unchanged. To enable
the dialect, follow the rollout steps in §7 of the design doc:

1. `add_subdirectory(Tvec)` in `include/CMakeLists.txt`.
2. Add a `TvecDialect` C++ library under `lib/` (registering the dialect, types,
   and ops generated by `TvecOpsIncGen`).
3. `registry.insert<mlir::tvec::TvecDialect>()` in `tools/ptoas/ptoas.cpp`.

None of these files have been compiled in the authoring environment; review and
build against `llvmorg-19.1.7` before relying on them.
